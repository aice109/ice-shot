# 路线图

IceShot 的功能全貌与后续规划。全部需求只分三块：**已完成**、**待办**、**已取消**。
不再按截取 / 标注 / 历史一类的能力域细分——找东西靠搜索，看优先级靠表格里的 P 级别。

**不变的底线**：本地处理、只在用户主动触发时截取、不静默上传。

**状态标记**

| 标记 | 含义 |
| --- | --- |
| ✅ | 已完成 |
| 🔜 | 计划中，尚未开始 |
| ❌ | 已取消，不做（保留记录以免重复讨论） |

**优先级**（只用于待办与已取消的排序参考，已完成项标 P0 表示属于核心能力）

| 级别 | 含义 |
| --- | --- |
| P0 | 核心能力 / 阻塞发版 / 安全与隐私 |
| P1 | 高频且投入可控，优先排期 |
| P2 | 有价值但可以等，用户有替代做法 |
| P3 | 长尾、锦上添花、需要额外条件才能启动 |
