# 设备壳：给截图加 MacBook 机身

给全屏截图套一层 **MacBook 机身外观**，用于对外展示（博客配图、产品落地页、演示材料）。

**进度（2026-10-26）**：N1–N4 已完成。机身按 Aluminium 材质重做一轮，
圆角、刘海、机身高光/内阴影均按真机观感调校。
第四节三个决定已拍板：只做 `.display` + `.allDisplays`、设备壳替换「窗口」档、天然互斥。

---

## 一、它与「带壳」不是同一件事

现有「带壳」（[screenshot-frame.md](screenshot-frame.md)）是**窗口隐喻**：把截图包成一个 APP 窗口。
设备壳是**产品照隐喻**：把截图包成「一台正在显示这张图的 MacBook」。

| | 带壳（已有） | 设备壳（本文） |
| --- | --- | --- |
| 隐喻 | 这是一扇窗口 | 这是一台设备 |
| 结构 | 内容 + 一层框 | 内容 + 屏幕 + 机身（**两层**） |
| 谁用 | 日常截图、发给同事 | 对外展示、做素材 |
| 遮挡 | 无 | 刘海会压住屏幕顶部 |

**结论：不塞进带壳的 `Chrome` 枚举。** 理由：

1. 结构不同。`ScreenshotFrameComposer` 现在是单层模型（内容 + 一圈留白 + 一个 `windowPath`），设备壳需要在外面再套一层机身，硬塞会让现有渲染器长出一堆 `if chrome == .device` 分支。
2. 语义不同。带壳是「这图怎么存」，设备壳是「这图怎么发出去」。混在一个开关里，用户点开「带壳」看到「MacBook」会困惑。
3. 尺寸预期不同。见第三节的成本。

**建议**：新增独立入口与独立渲染器，共用「输出设置」的位置（复制 / 保存之前），但**不复用**带壳的 popover。

## 二、视觉规格

以**屏幕内容宽度** 1000 px 为 1 单位（与带壳一致，便于共用)。

### 2.1 结构：单层机身（已定）

**不做底座。** 曾按 Apple 官网产品照实现过「上盖 + 间隙 + 底座」三层结构，
实机观感反而不如单层：底座太薄时像一根棍子，加厚又抢内容。
最终回到单层机身——它就是「一台 MacBook 的屏幕部分」，干净、不干扰内容。

```text
┌──────────────────────────────┐  ← 机身（圆角矩形）
│  [刘海]                       │
│         屏幕内容               │
└──────────────────────────────┘
        ↕ 外边距 + 投影 + 可选背景
```

### 2.2 几何规格（单位 u，内容宽 1000 = 1u）

| 项目 | 值 |
| --- | --- |
| 机身边框 | 8 |
| 屏幕黑边 | 16 |
| 机身圆角 | 30 |
| 屏幕圆角（**仅上面两角**） | 34 |
| 刘海宽 × 高 | 116 × 24 |
| 刘海圆角（四角同半径） | 24 × 0.45 ≈ 11 |
| 下巴 | 22 |

两条容易踩的坑，都写在代码注释里：

1. **屏幕圆角必须大于黑边厚度**。黑边 16u，若屏幕圆角取 14u，
   弧度整段被黑边吃掉，肉眼完全看不出来——取 34u 才留下约 18u 可见弧度。
2. **屏幕只有上面两角是圆的**。下面两角是直角，这是最新 MacBook 的特征；
   四角全圆会显得像老款 iPad。

### 2.3 机身材质

机身不是单一填充色，而是四层叠加：

1. **双层落影**：近处紧、远处散，模拟环境光遮蔽；
2. **四点竖直渐变**（`highlight → upper → lower → shade`，位置 0 / 0.18 / 0.62 / 1）：
   上缘受光、中间平缓、下缘转暗。两端渐变会显得像塑料，所以用四个停靠点；
3. **外沿高光**：直接沿机身路径描边，外半被画布裁掉、内半留成贴边亮线；
4. **内沿阴影**：贴着黑边区外圈压一道暗边，把屏幕「嵌」进机身。

> 曾经单独造过一条「内缩路径」画高光，但圆角半径没同步缩，两者不同心，
> 转角处露出错位的白边。直接沿机身路径描边即可，不需要第二条路径。

屏幕玻璃底不是纯黑而是极深灰（银 `#16171A` / 深空灰 `#0E0F11`），
刘海与玻璃同色 + 极细暗描边——真机刘海是连续挖孔，不是贴上去的黑块。

### 2.4 刘海形状

刘海是**四角同半径的圆角矩形**（半径 ≈ 高度 × 0.45），用三次贝塞尔绘制。
它压在屏幕顶部正中，与屏幕玻璃同色 + 一道极细暗描边。

比例参考真机：刘海约占屏宽 11%～12%，因此取 116u（屏宽 1000u）。
| 机身描边 | 1（浅灰高光 + 深灰内描边两层） |
| 机身色 | 银 `#E3E4E6` → `#C8C9CC` 竖直渐变；深空灰 `#4A4A4E` → `#2E2E31` |
| 投影 | 模糊 60u、向下 24u、透明度 0.30 |
| 外边距 | 小 28u / 中 52u / 大 76u（比带壳略小，机身边缘本身就留出了视觉重量） |

### 2.5 刘海与遮挡

真机刘海**压在屏幕上**。三个可选策略：

| 策略 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A. 遮罩**（默认推荐） | 刘海画在内容之上，内容不挪 | 最接近真机观感 | 吃掉顶部 14u 的内容（1000px 宽时约 14px） |
| B. 留黑边 | 内容整体下移 14u，刘海两侧露黑色屏幕底 | 不遮内容 | 顶部有可见横条，观感不像真机自拍图 |
| C. 无刘海 | 只画均匀黑边 | 完全不干扰 | 观感像 2015 款老机器，削弱「MacBook Pro」识别度 |

**已采用 A（遮罩）**。刘海从**内容区上沿**往下长、上沿贴黑边。
它画在内容之上，所以会遮住顶部中央约 107×19u 的内容。

形状：两侧下角半径 ≈ 高度的 0.92（接近半圆的「耳朵」），
上角也收 35% 高度，整体是一颗圆润挖孔而不是方形黑标签。

实测：全屏截图的顶部通常是菜单栏，而菜单栏中间的 56×16u 区域一般是空的（图标在两侧），
落在刘海区域的概率不高。因此暂不做「检测顶部内容并降级」的自动策略。

> 但如果用户是「全屏截图」并要求设备壳，顶部通常是菜单栏——菜单栏中间是空的（图标在两侧），
> 落在刘海区域的概率不高。实测后再决定是否保留降级。

### 2.6 机身外观两档

| 外观 | 机身渐变 | 描边 |
| --- | --- | --- |
| 银 | `#E3E4E6` → `#C8C9CC` | 外 `#FFFFFF` 60%，内 `#8E8E93` 25% |
| 深空灰 | `#4A4A4E` → `#2E2E31` | 外 `#8E8E93` 40%，内 `#1C1C1E` 60% |

### 2.7 背景

复用带壳已有的 5 档背景（透明 + 石墨 / 海蓝 / 晨曦 / 极光）。
「发出去用」的场景几乎总要背景，建议**默认石墨**而不是透明。

## 三、代价与风险（先看清再做）

1. **导出尺寸显著变大。**
   1000×640 的内容，套上机身约 1060×760，再加外边距约 1164×864。
   放大到 Retina（内容 2000px 宽）时，输出约 2328×1728。这是「产品照」的合理代价，但需要确认。

2. **视觉规格必须重写。**
   带壳那 60 行规格是窗口几何（标题栏 28u、交通灯 12u），设备壳需要一整套新几何。
   两者唯一能复用的是**背景渐变与投影**。

3. **渲染器要分层。**
   现在 `ScreenshotFrameComposer.render` 一次画完。设备壳需要：
   内容 → 裁屏幕圆角 → 叠刘海 → 画机身 → 投影 → 背景。
   建议新增 `DeviceFrameComposer`，不改造现有渲染器——两者分支交叉会让两边都难维护。

4. **不能假装是真机截图。**
   这是诚实性问题：设备壳是**装饰**，不该被误解为「IceShot 能在 Mac 上截出带机身的图」。
   建议在界面上明确写「展示用外框」，并**默认不开启**。

5. **新增文案需要中英双语**，`LocalizationTests` 会卡住漏翻。

6. **不新增权限、不联网、不改 SwiftData**。设备壳是纯渲染，不碰这些。

## 四、待你拍板的三个决定

动手前必须定这三件事，否则做出来要返工：

### 决定 1：刘海策略（已定：A 遮罩）
- **A 遮罩**（最像真机，会吃掉顶部约 14px）
- B 留黑边（不遮内容，顶部有横条）
- C 无刘海（最干净，但不像 Pro）

我推荐 **A**，并在检测到顶部有内容时自动降级到 B。

### 决定 2：尺寸档位（已定：只做一档）
- 只做 14 吋 16:10 一档？
- 还是按内容比例自动选（内容接近 16:10 用 14"，接近 4:3 用其它）？

已定：**只做一档**，与内容比例无关（机身外形固定）。

> 注意：内容按原比例直接画进屏幕，**不做等比留黑边**。全屏截图本来就是 16:10 左右，
> 不匹配的情况（如 4:3）会轻微拉伸观感，但不会引入黑边。

### 决定 3：入口位置（已定：并入带壳的 `Chrome`）
- 与「带壳」并列，在输出胶囊里多一个按钮？
- 还是放进「带壳」popover 里作为一个「展示壳」页签？

改按用户决定：**不新增按钮**，而是作为 `Chrome` 的一档 `.macbook` 并入现有带壳面板。

来源规则（`ScreenshotFrameStyle.allowedChrome(for:)`）：

| 来源 | 可选壳形态 |
| --- | --- |
| 窗口 | 仅阴影（画面自带交通灯） |
| 全屏 / 全部显示器 | **MacBook** / 仅阴影（「窗口」档被设备壳顶替） |
| 区域 / 长截图 | 窗口 / 仅阴影 |

这样 `.macbook` 与「窗口」在任何来源下都不会同时出现，天然互斥。
`.macbook` 只是入口，渲染转交 `DeviceFrameComposer`。

## 六、明确不做

- 不做手机壳（iPhone / iPad）：与本项目「macOS 截图工具」定位不符。
- 不做假菜单栏 / 假 Dock / 桌面壁纸：会让成品图看起来像伪造的截图。
- 不读取真实机型信息：机身是固定矢量绘制，不依赖系统版本。
- 不把设备壳烘焙进历史库：历史永远存原图。
